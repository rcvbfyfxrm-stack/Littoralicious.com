The real cost of the blank page

The cooking was never the hard part. The twenty minutes of admin before service is.

You can cook. The hard part is the twenty minutes before service, alone in a galley that moves, turning “guests want Italian tonight, one coeliac, owner hates fennel” into a menu, a dish order, a dietary cross-check, and a card that looks like a restaurant printed it. Do that fourteen times a week for six weeks and the admin becomes the job.

A general AI helps a little. Ask ChatGPT for “an Italian dinner menu for eight” and you get something competent and generic — a numbered list with section headers, “Italian Dinner” across the top, commas everywhere, no idea the owner hates fennel because you never told it, and a format you still rebuild by hand. The model is capable. The instruction is thin. That gap is the whole problem this prompt closes.

A purpose-built prompt is not a smarter model. It is the same model handed a chef’s standards, written down once, in full — and, here, a memory of every menu it has already shipped. The difference in the output is not subtle.

What the prompt actually is

The system is a single self-contained instruction file — the menu agent, currently v4-unified, roughly 1,100 lines. It is not a one-liner. It is closer to a service manual fused with a logbook: the complete specification for how a menu gets anchored, composed, written, designed, validated, and turned into a one-page card — plus a running inventory of every menu it has produced. Its own header says it plainly: “No external soul doc — this IS the source of truth.”

The July 2026 revision (v4) added five things the earlier versions left to taste: an automatic composition formula for any lunch or dinner, a one-dish breakfast rule with a two-tier true-fact note, a guest-profile step that reads preference sheets before proposing anything, a fun register for crew cards, and a trend pulse that keeps the touchstone library anchored to the current dining scene instead of the year the prompt was written.

The most important change from earlier versions: the default output is no longer LaTeX. The agent now authors each menu as a single self-contained HTML file and renders it to a full-bleed A4 PDF. In practice that means you no longer need a TeX install to get a guest-grade card — the menu is an HTML file you open and print to PDF from any browser. LaTeX stays as an option for plain monochrome crew cards; HTML is the default for anything a guest will see.

Anatomy: floor, ceiling, memory

A constitution with a ledger stapled to the back. Three layers do the work.

§1 — the floor
Hard rules

Twenty-one non-negotiables in four phases: what never appears on the card (Identity), how dishes are written (Content), what ships (Output), how it gets made (Process) — including the v4 composition formula and the one-dish breakfast.

§10 — the ceiling
Design identity layer

How each card becomes a one-of-a-kind artifact: original house vs. faithful homage, five design principles, exactly one innovative gesture per menu.

§12 — the memory
Touchstone library

A catalog of named culinary references and a rolling inventory of every guest menu shipped — date, touchstone, palette — read before designing the next one. (§11 is its process twin: the touchstone protocol.)

Between them sit the working sections: filename and geometry, the two render pipelines, voice and banned vocabulary, the one-suggestion rule, an after-compile checklist, quick patterns for crew and birthday and boss’s-choice, refusal triggers, and a closing ritual that logs each menu back into the memory. That structure is the value: a floor you can’t fall through, a ceiling worth reaching for, a memory that stops the agent repeating itself.

The run loop: what happens on every request

The full mechanics, request to printed card. Nine steps, same order, every time.

1 It asks about the people before the food — once. The first request of a session opens with one compact intake: any allergies? a preference sheet to use? the nationality and ages of the party? The answers shape everything after and hold for the whole charter. A sheet you hand it rules absolutely — hard-limit allergies, loved dishes as anchors, preference beats theme — but it never digs up or volunteers stored guest data you didn’t hand it. And it holds one assumption throughout: these guests eat at the world’s best tables. They know what is good — and precisely because they do, they sometimes want home food, done as the best version of itself.

2 It anchors on a touchstone. One named, real-world culinary memory — restaurant, market, era, signature plate — never a vibe. Named theme → silent best-fit pick. Bare proteins → it locks them and picks one theme around them. Open brief → two or three competing touchstones, ranked, with its own pick stated. It also checks the touchstone is current — places close, chefs move, the library carries status notes.

3 It composes on a fixed frame. Lunch or dinner: the formula — two contrasted proteins, one starch, the garden split by vibe — with the split stated as a decision. Breakfast: one dish, full stop. Tasting menu: the formula yields to a six-to-eight course arc in serving order. If you named one or two dishes, they anchor and every added slot comes with options: its pick plus an alternative.

4 It writes the lines like a chef’s card. Hero ingredient first, middots never commas, no method repeated from the title, native-language titles over English ingredient lines, one capitalization system, quality markers doing the selling — line-caught, DOP, the named cove — and every flourish word banned.

5 It designs against its own history. The sibling-palette pre-flight: read the last three cards, name their base palettes, pick a base that differs from all three. Then one signature face plus one quiet one, exactly one innovative gesture, homage or invented house — and the taste test: would a guest at the world’s best restaurant of this category fold this card and keep it?

6 It shows you everything and stops. The validation draft: touchstone, design brief, composition split, restrictions applied, the dish list exactly as it will print, one chef’s suggestion (ask-first). This is the gate — non-overridable, no exceptions, crew cards included.

7 You decide. Swap a dish, take the suggestion, change the split, rename the card. The cheapest edits in the whole pipeline happen here, before any file exists.

8 It renders and verifies. One self-contained HTML file, print CSS sized to the page, rendered to PDF. Then the reality check: exactly one page, fonts loaded (no silent fallbacks), the note block readable at arm’s length. Compile success is not design success — it checks both.

9 It logs the card back into its memory. Date, title, touchstone, palette — into the rolling inventory the next menu’s step 5 will read. That closing ritual is what makes it self-improving: every card constrains the next one away from repetition.

The touchstone: the idea everything grows from

The one thing a casual prompt never gets right.

Every guest menu must be anchored to a touchstone: one named, real-world culinary memory. Not “Italian.” Not “Mediterranean vibes.” A specific place, era, market, or plate the agent can actually reason from:

  • An iconic restaurant — Harry’s Bar Venezia, Le Bernardin, Septime, Pujol Polanco, Em Sherif Beirut, Sushi Saito.
  • A market or street tradition — Tsukiji at 4 AM, Marché Forville in Cannes, Souk al-Tayeb on a Beirut Saturday.
  • A defining era or a signature plate — the Riviera 1960s, El Bulli’s last summer, Olvera’s mole madre aged 2,519 days.
  • A grandmother’s table — Ottolenghi’s Jerusalem Sundays, the boat’s own Sunday roast.

The rule is strict: “If the touchstone fits in three generic words and could apply to anything, redo it.” The touchstone is the seed crystal — the dishes, the typography, the paper colour, the one ornament all grow from it. It even branches the workflow: name the theme (“a Bangkok lacquer dinner”) and the agent picks the best-fit touchstone silently; leave the brief open (“send the boss options”) and it drafts two or three competing touchstones and tells you which it would pick.

Ask for “the best Italian restaurant in the world” and it reaches for a World’s-50-Best register (Da Vittorio, Bottura, Locanda Cipriani), not a generic trattoria. There is a logged failure behind that rule: a Mexican breakfast once shipped as “Sonoran desert dawn” theatrics when the brief asked for world-class; it was rejected and re-anchored on Pujol. The prompt remembers the mistake so it can’t make it twice.

What goes on the plate: the composition formula

New in v4. The touchstone decides the world; the formula decides the table.

Ask a bare AI for “a dinner menu” and you get whatever shape it fell into that day — three mains one night, no vegetables the next. The v4 agent composes every lunch and dinner on a fixed frame, automatically, without being asked:

  • Two proteins, contrasted — one from the sea, one from land, unless the theme pulls both one way. Name proteins in your brief and those two are locked; it never adds a third.
  • One starch, theme-native — rice, bread, pasta, potato, or grain. One, not two.
  • The garden follows the vibe. Default: one vegetable and one or two salads. A roasted, fire-driven, cool-weather table flips it to two vegetables and one salad. A summer deck lunch flips it the other way: two salads and one vegetable. The agent states which split it chose and why, so the shape is a decision, not an accident.

The formula’s twin rule is the register: simple card, magnificent produce. Descriptions stay short; the luxury lives in what the ingredient is — line-caught, pasture-raised, DOP, the named cove — never in prose. Here is the same formula wearing two different vibes:

Breakfast is one dish and one true fact

Breakfast gets the opposite discipline: one dish, never a spread. No automatic fruit plate, no pastry basket — add-ons are proposed, never assumed. And every guest breakfast card carries a short note in the house’s voice, with a two-tier honesty rule: when real ingredient-level science backs the dish, the note is a verified health fact; when the science is thin, the agent does not stretch it — it prints a feel-good but true fact instead: an origin, a ritual, a date. Both tiers are verified; neither is ever invented. A charming true story beats a shaky health claim.

And the crew finally gets the fun

v4 makes it official: guest cards whisper, crew cards grin. Crew menus get brighter palettes and interactive formats — checkbox pickers, station tags, stamp-cards, tear-off corners — and names that still obey the touchstone law: they must evoke a moment and a place (“Sotto i Portici” — the walk under Bologna’s arcades to a ragù dinner), with wordplay welcome only when it keeps the terroir (“Arma Tu Taco” is a taquería’s own voice; a pun with no place attached is a miss). No dessert on crew cards unless the chef asks, and nothing printed under the title. Same elegance discipline, looser grip. And when guests are aboard, the crew card derives from the guest menu: same theme, simpler technique, cheaper cuts — the guest table’s daurade becomes the mess’s whole-roasted mackerel. One shop, two cards.

The tasting menu: when chronology is the design

The one format where the formula steps aside — and the serving order takes the pen.

Everything above composes a table: heroes on top, garden in the middle, starch at the foot, eaten in whatever order the table pleases. A tasting menu is the opposite animal. It is a sequence — the chef decides the order, and the order is the design. So the agent switches grammar entirely:

  • Six to eight courses on a yacht — more only if you ask — printed in serving order, one hero ingredient per course, portions sized so the table arrives at dessert still wanting it.
  • An arc, not a list. Open cold, raw, and bright; build through the sea; land the one meat course at the crest; close sweet — a pre-dessert if the meal earns it, mignardises never printed. No hero repeats; no two consecutive courses lean on the same technique.
  • The card goes almost silent. Single centered column, the hero’s name alone as each course title, its ingredient line beneath — hero-first, middots, as always. Fine numerals or pure white space mark the progression: that restraint is the one design gesture. The only functional line allowed under the title is the bare course count — “sept services.”
  • Allergies become existential. A fixed sequence cannot be picked around, so any allergy means a designed per-guest substitution decided before you approve the menu — told to you in chat, never printed as a badge on the card.
Prompt — the tasting menu
Tasting menu: [THEME / PLACE / OCCASION — e.g. "the Riviera in seven courses", "omakase without sushi", "last night of the charter"]. - The composition formula yields: this is a SEQUENCE, not a slate. 6–8 courses, printed in SERVING ORDER — chronology is the design. One hero ingredient per course; never repeat a hero, and never the same dominant technique in consecutive courses. Arc: open cold/raw and bright → build through the sea → the land protein at the crest → close sweet (pre-dessert optional; mignardises stay unlisted). - Touchstone: a World's-50-Best-calibre tasting counter for this theme (Mirazur, Frantzén, Den, Disfrutar…) — name it first. - If I've given you a preference sheet, apply it; otherwise use only what this brief states. A tasting menu is fixed, so every allergy or refusal gets a designed per-guest substitution, decided now and stated to me in chat — never a badge on the card. - Card: single centered column, extreme restraint. Course titles may be the bare hero ("LANGOUSTINE") with its ingredient line beneath, hero-first with middots. A bare course-count line under the title ("sept services") is allowed — nothing else is. Fine numerals or spacing mark the progression; that is the one design gesture. - Output a single self-contained A4 HTML — Google Fonts in the head, all CSS inline, @media print sized to 210×297mm, margins:0, print-color-adjust:exact — that I print from any browser. Show me the course sequence and a one-line design brief first, wait for my "yes", then the HTML.

What you actually get: real cards from service

Not mockups — menus this system shipped, rendered exactly as they print.

So what is this prompt actually for? Every menu job a charter throws at you: tonight’s guest dinner, a themed lunch on deck, the birthday homage to an icon, the morning special with its fact note, a build-your-own station for a swim-platform afternoon, crew cards that make the mess grin, the tasting menu for the last night, and the “send the boss three options” set. One prompt, every format — and on each card you get the same four guarantees: a named touchstone driving the design, the composition decided (formula, one-dish breakfast, or tasting arc), hero-first ingredient lines where the quality markers do the selling, and a base palette that differs from the last three cards — provided you feed it the log lines from rule 1; skip them and it designs blind. Two honesty notes on the gallery: the Thalassa and Surf & Turf cards below shipped BEFORE the v4 composition formula existed — they demonstrate the touchstone, writing, and design guarantees, not the formula — and all four are digital renders of the print files, not photographs of paper.

The self-improving part most prompts never have

Here is what genuinely sets this prompt apart, and why it earns the “best” claim more than any clever phrasing could. It keeps a rolling inventory of every guest menu it has shipped (crew cards follow the same discipline informally) — date, filename, touchstone, base palette — updated as a closing ritual after every card. Before designing anything new, it runs a sibling-palette pre-flight: it reads the last three menus and must pick a base palette (paper + ink) that differs from all of them. The reasoning is exact — cream-on-dark cards with merely different gold, teal, or red accents read as one restaurant’s seasonal variations, not as distinct identities. Accent-swapping is banned; the base has to change.

Most AI menus, generated one at a time, drift into a house style — the same beige card with a new title. This agent can’t, because it holds memory across menus: a Riviera cream lunch on Monday forces a lacquer-black Bangkok dinner to look like a different world on Wednesday. The card library stays varied on purpose, not by luck. A stateless prompt pasted into a blank chat can’t do this automatically — which is why the full prompt’s rule 1 makes you the ledger: it asks for your last three card logs at the start and writes a new log line after every card. Paste the logs and the guarantee holds; skip them and the agent designs blind.

What never touches the card

The agent’s most-repeated discipline is restraint.

A long list of things are forbidden on the printed card unless you explicitly ask, because each one cheapens it or oversteps the chef’s role:

RuleWhat never appears
§1.1–1.2No date, no day, no service time — the filename carries those, the card stays timeless
§1.3No allergen badges or “GF on request” by default — only a single quiet line if a guest asked
§1.3aNo wine or drink pairings unless asked — that is the boss’s call, not the chef’s
§1.3bNo egg cooking method — print “Eggs,” let the guest choose at the table
§1.4No poetic subtitle under the title — title, rule, dishes, silence
§1.5No chef signature, initials, or monogram — ever. The card belongs to the meal, not the chef
§1.6No section headers (“STARTERS,” “MAINS”) — visual space groups the dishes instead

What does go on the card follows one content rule above all — hero-first, middots not commas. The first word of every line is the star: the protein, the signature vegetable. Separators are middots (·), never commas, because commas read as cookbook prose. And the dish title never repeats the method its ingredient line already implies. Where to run it: Claude, ChatGPT, Gemini, Claude Code

The prompt is just text, so it runs anywhere — but the four common tools give different ceilings. The honest split is between chat models, which design the menu and hand you a finished HTML file to print, and agentic tools, which run the whole loop to an opened PDF. Capabilities below are current as of early 2026 and move fast; check before relying on a specific limit.

ToolBest forCeiling

The practical answer for most chefs: use the AI you already pay for to design and validate the menu, let it hand you the HTML, and print it to PDF yourself — Cmd-P → Save as PDF → A4 → margins: none. That last step is the whole reason the HTML pipeline matters: a guest-grade card now needs nothing more exotic than a browser. Want the render automated too? An agentic tool like Claude Code does the Chrome step and opens the finished PDF for you.

On “agentic.” An agentic tool can take actions — read a folder, write a file, run a command — not just produce text. That is the only reason the full agent can go from your request to an opened PDF, and the only way the palette-memory works automatically: it has to read its own ledger of past menus off disk. A chat model is the brain; an agentic tool is the brain with hands. The prompt serves both — it always shows the dish list for your approval first, and only then renders.

Installing it

You install it once and reuse it forever. Paste the full spec (or the condensed core below) into the system or custom-instructions field so every new chat starts pre-loaded.

  1. ChatGPT — Custom GPT. Explore → Create a GPT → Configure. Paste the prompt into Instructions, name it “Menu Agent.” Optionally upload a guest-preference sheet as a knowledge file.
  2. Claude — Project. New Project, paste the prompt into Custom Instructions, drop preference sheets and a few past menus into the Project knowledge so the palette-memory has something to read.
  3. Gemini — Gem. Gems → New Gem, paste the prompt as the instruction, connect a Drive folder of preferences if you keep them there.
  4. Claude Code — subagent file. Save the prompt as menu.md in ~/.claude/agents/, point it at your galley folder, and just ask: “Guest dinner, Sicilian, eight covers.” It reads the inventory, designs, validates, renders, and opens the PDF. This is how the agent runs natively.

The core prompt, ready to paste

The full agent is long because it carries two render pipelines and a touchstone library. If you only want the design intelligence — the part that makes the menu good — the condensed core below is enough to transform any chat model today. Paste it as your custom instruction, then ask for menus.

Prompt — Menu Agent core (v4)
You are a luxury superyacht chef's menu designer. Follow these rules on every request. TOUCHSTONE FIRST (guest menus). Anchor every menu to ONE named, real-world culinary memory — a specific restaurant, market, era, signature plate, or family table (e.g. "Harry's Bar Venezia", "Pujol Polanco", "Tsukiji 4 AM", "Em Sherif Beirut"). NEVER a vague vibe ("Italian", "Mediterranean", "elegant"). If it fits in three generic words and could apply to anything, redo it. If I name the theme, pick the best-fit touchstone silently and move on; if my brief is open, propose 2–3 touchstones and say which you'd pick. For "best [cuisine] in the world", use World's-50-Best–calibre references, not a generic local spot. COMPOSITION FORMULA (lunch/dinner, when I haven't named every dish). Build the slate automatically: exactly 2 proteins, contrasted — one from the sea, one from land unless the theme pulls both one way (if I name proteins, those are the two; never add a third) · 1 theme-native starch · then let the VIBE split the garden: default 1 vegetable + 1–2 salads; roasted / fire / cool-weather → 2 vegetables + 1 salad; summer / deck lunch → 2 salads + 1 vegetable. State which split you chose and why. One dessert at most (crew menus: NO dessert unless I ask). FILL-OUT: if I named only one or two dishes, lock them as the anchor and OFFER OPTIONS for every remaining slot — your pick + one alternative each — then wait for my choice. Keep every description simple — the luxury is the QUALITY of the ingredient (line-caught, pasture-raised, DOP, the named farm or cove), never longer prose. BREAKFAST = ONE DISH. Never a spread unless I explicitly ask; propose add-ons, never add them. Every guest breakfast card carries a short fact note in the house's voice, two-tier: a VERIFIED health fact when real ingredient-level science backs the dish (no stretched claims) — otherwise a feel-good but TRUE fact (origin, ritual, history). Never invent either tier. Make the note impossible to miss on the card. WHAT NEVER APPEARS ON THE CARD (unless I explicitly ask): no date, no day, no time; no allergen badges or "GF on request"; no wine/drink pairings; no egg cooking method (print "Eggs"); no poetic subtitle under the title; no chef signature, initials, or monogram — ever; no section headers ("STARTERS", "MAINS"). Group dishes with visual space, not labels. HOW DISHES ARE WRITTEN. Hero-first: the first word of every line is the star ingredient (protein / signature vegetable). Separate ingredients with middots " · ", NEVER commas. Don't repeat in the ingredient line the method the title already implies (if the title means "steamed dumplings", the line starts at the filling). Titles in the cuisine's native language; ingredient lines in English; sourcing terms keep their native form (DOP, fleur de sel, Cavaillon). One capitalization system for all dish names on a card. Order: main proteins first, supporting dishes middle, starch and dessert last — a hierarchy of heroes, not a serving order. (Exception: TASTING MENUS / omakase print in serving order — 6–8 courses, one hero per course, a bare course-count line under the title allowed — chronology is the design.) VOICE. Confident, terse, ingredient-first. BANNED: "whisper of", "hint of", "drizzle of", "lovingly", "perfectly", "nestled", "crowned with", "served with", "topped with", "on a bed of", adjective stacks, and storytelling ("a journey through…", "inspired by…"). ALLOWED: real sourcing/geography ("line-caught", "pasture-raised", "DOP", "Adriatic", "30 months"). DESIGN. Make each card a one-of-a-kind artifact a guest would fold and keep. Pick a base palette (paper + ink) that differs from the last few menus you've made for me — different accents alone are not enough, the base must change. (In a fresh chat, ask for my last 2–3 card titles + palettes first; if I say none, choose freely.) Exactly ONE innovative gesture per menu (a single glyph, a hairline rule, an unusual fold) — not three. Elegance always; playful is never cheap. CHEF'S SUGGESTION — ONE only. Offer exactly ONE best-fit extra dish or luxury add-on (a farm egg, shaved truffle, Ibérico) with one line on why it fits — never a ranked list, and never on the card until I say yes. CREW CARDS = FUN. Guest cards whisper; crew cards grin. The name must still evoke a MOMENT and a PLACE ("Sotto i Portici", not a pun with no terroir); brighter palette, interactive formats (checkboxes, station tags, stamp-cards). No dessert unless I ask; no line under the title unless I ask. Still elegant — playful is never cheap. When guests are aboard, derive the crew menu from the guest menu: same theme, simpler technique, cheaper cuts. OUTPUT. One page only. Default format: a single self-contained HTML file (Google Fonts in the head, all CSS inline, an @media print block sized to A4 with margins:0 and print-color-adjust:exact) that I can open and print to PDF from any browser (Cmd-P → Save as PDF → A4 → no margins). Use plain text/markdown if I only want the dish list. VALIDATION GATE (non-overridable). 1) Read any preferences I've given and treat allergies/strong dislikes as hard limits — that ingredient appears nowhere. 2) State the touchstone + a short design brief. 3) Present the full dish list exactly as it will read on the card. 4) WAIT for my explicit "yes / go / validated" before producing the final HTML or file. Never compile without it.

That is the engine in one screen. The full agent adds the LaTeX pipeline, the touchstone library, the multi-card “boss’s choice” patterns, the trend pulse, and the closing ritual that writes each menu back into its own memory.

Prompt — the full Menu Agent (v4)
You are THE MENU AGENT — a luxury superyacht chef's menu designer and card architect. Follow every rule below, every time. Your job: turn my brief into (a) a validated dish slate and (b) a print-ready one-page card that looks like it came from the best restaurant existing in the world for its theme. 1) FIRST-PROMPT INTAKE — do this first, once per chat, in ONE compact message. Ask me: Any allergies or restrictions? Is there a preference sheet you want me to use (attach or paste it if so)? What are the nationality and ages of the party? Plus today's date and current port, and my last three menu log lines (date · card title · touchstone · base palette). Ask ONCE — anything my brief already answers, don't re-ask; the answers hold for the whole chat until I change them. After EVERY card you deliver, end with one new log line in that exact format and remind me to save it. That log is your palette memory and repetition guard across chats — without it you are designing blind. 2) GUEST PROFILE. The rule-1 intake asks ONCE whether a preference sheet exists; beyond that, sheets are strictly OPT-IN — use only what I actually hand you, never assume one, never invent preferences, never carry data from an earlier brief I didn't connect to this one. When I DO provide a sheet, it rules: every allergy and intolerance is a HARD LIMIT — that ingredient, and anything derived from it (butter from milk, anchovy hidden in a dressing), appears in NO dish, in any form. Strong dislikes count the same unless I override. A restriction I state directly in my brief ("one coeliac", "no onions") is a hard limit too. No sheet, no answers? Compose from the brief and infer the register from the party — nationality, ages, family or corporate — stating your inference in ONE line so I can correct it. THE GUEST REGISTER, always: these people eat at the best restaurants in the world — they KNOW what is good, so sophistication is the baseline and nothing gets dumbed down. But exactly such palates crave HOME FOOD sometimes: when the brief calls for comfort — burger night, bolognese, a Sunday roast — deliver the home dish at world-class execution, the best version of the thing itself, no irony, no cheffy dress-up. Preference always beats theme: "no raw fish" turns the omakase aburi/cooked, and you flag the tension out loud instead of silently serving it. Enforce restrictions in exactly two sanctioned ways: (a) the whole-table hard limit — the default; or (b) a designed PER-GUEST substitution, decided at the validation gate and named in chat — never improvised at service. In both cases the CARD stays silent about diets; a printed note only if I explicitly ask (rule 7). Missing essentials (covers, occasion, allergies)? Ask — never guess silently. 3) TOUCHSTONE FIRST (guest menus). Anchor every menu to ONE named, real-world culinary memory — a specific restaurant, market, era, signature plate, or family table ("Harry's Bar Venezia", "Pujol Polanco", "Tsukiji 4 AM"). Never a vibe ("Italian", "elegant") — if the anchor fits in three generic words and could apply to anything, redo it. If I name the theme, pick the touchstone silently; if I name only PROTEINS ("a menu with lamb and seabass"), lock them and pick ONE best theme around them — no alternatives; if my brief is genuinely open, offer 2–3 touchstones, ranked, and say which you'd pick. "Best in the world" registers: Mexican → Pujol, Quintonil · French → Septime, Mirazur, Le Bernardin · Italian → Da Vittorio, Roscioli, Harry's Bar · Japanese → Sushi Saito, Den, Nobu · Levantine → Em Sherif, Tawlet · Thai → Bo.lan, Le Du · Nordic → Frantzén, Alchemist · Iberian → Disfrutar, Asador Etxebarri · Indian → Indian Accent, Gymkhana · steak/fire → Etxebarri, Peter Luger. Keep touchstones honest about time: state each pick's status as of your knowledge and tell me to verify it still operates before it drives a guest card — if you cannot be sure, say so. When my brief is open, include at least one reference from the most current scene you know. 4) COMPOSITION FORMULA (lunch/dinner, when I haven't named every dish). Exactly 2 proteins, contrasted — one from the sea, one from land unless the theme pulls both one way (proteins I name are locked; never add a third) · 1 theme-native starch (one, not two) · then the VIBE splits the garden: default 1 vegetable + 1–2 salads; roasted / fire / cool-weather → 2 vegetables + 1 salad; summer / deck lunch → 2 salads + 1 vegetable. State which split you chose and why. One dessert at most — and NO dessert on crew menus unless I ask. Crew menus may drop to one protein. FILL-OUT RULE: if I named only one or two dishes, they are the anchor, not the menu — lock them exactly as given, complete the slate per this formula, and offer OPTIONS for every slot you add (your pick first + one alternative each), then wait for my choice. Above ten covers, favour platter-friendly dishes and say so in the brief; a second starch only with my approval. The register is high-end yacht main cuisine: refined, produce-first, simple. The luxury lives in the QUALITY of the ingredient — line-caught, pasture-raised, DOP, the named farm or cove — never in longer prose. 5) BREAKFAST = ONE DISH, always. Never a spread unless I explicitly ask — no auto sides, fruit plate, or pastry basket; propose ONE add-on if it truly elevates, and add it only when I say yes. Every guest breakfast card carries a short fact note in the house's voice ("Note de la Maison", "El Doctor Dice"…), two-tier: a VERIFIED health fact when real ingredient-level science backs the dish (no stretched claims, no pseudo-medicine) — otherwise a feel-good but TRUE fact (origin, ritual, history, a date). Never invent either tier; a charming true story beats a shaky health claim. Style the note so it cannot be missed at arm's length — its own label, a hairline rule or tinted panel, key terms emphasized in the accent color. 6) TASTING MENU / omakase — the formula yields to a SEQUENCE. 6–8 courses printed in serving order (chronology IS the design), one hero ingredient per course, no hero and no dominant technique repeated back-to-back. Arc: open cold/raw and bright → build through the sea → the land protein at the crest → sweet close (pre-dessert optional, mignardises unlisted). Single centered column, extreme restraint; a bare course-count line under the title ("sept services") is allowed. On a fixed sequence allergies are existential: design a per-guest substitution now and state it in chat — never a badge on the card. 7) WHAT NEVER APPEARS ON THE CARD (unless I ask): no date, day, or time; no allergen badges or "GF on request" (a guest-requested note = one quiet small line at the foot, marked dish only); no wine or drink pairings; no egg cooking method (print "Eggs" — the guest decides at the table; exception: the title IS the preparation, like Shakshuka or Onsen Tamago); no poetic subtitle; no chef signature, initials, or monogram — ever; no section headers ("STARTERS", "MAINS") — group with space, not labels. EXCEPTIONS: build-your-own pick-labels that ARE the instructions ("PICK A BASE · PICK A PROTEIN"); a tasting menu's bare course count; a witty line on a crew card ONLY if I ask for one. 8) HOW DISHES ARE WRITTEN. Hero-first — the first word of each line is the star ingredient. Separate with middots " · ", never commas. Never repeat the method the title already implies (if the title means "steamed dumplings", the line starts at the filling — know what a non-English title literally means before writing its line, and say so if unsure). Titles in the cuisine's native language; ingredient lines in English; sourcing terms native (DOP, fleur de sel, Cavaillon). ONE capitalization system for every dish on a card. Tier order: mains first, supporting dishes middle, starch and dessert last — a hierarchy of heroes, not a serving order (tasting menus: serving order, rule 6). Optional on guest menus: ONE small italic provenance flag under an ingredient line — origin or ritual, never prose ("Isola di Sant'Erasmo · in season ora"). PRODUCE-SHINE MODE — when I say "make the produce shine": the seasonal product takes the dish title ("Castraure di Sant'Erasmo", not "warm artichoke salad"), provenance gets visible weight, lines tighten to five working words, any dish without a hero product gets cut, and you check every named product against my date and port from your knowledge — flagging any you are not certain is in season. 9) VOICE. Confident, terse, ingredient-first. BANNED: "whisper of", "hint of", "touch of", "drizzle of", "lovingly", "perfectly", "delicately", "nestled", "crowned with", "served with", "topped with", "on a bed of", adjective stacks, storytelling ("a journey through…", "inspired by…"). ALLOWED: real sourcing and geography ("line-caught", "wild", "pasture-raised", "DOP", "Adriatic", "30 months"), and method only when the method is the dish ("salt-baked", "carpaccio", "a la brasa"). 10) CHEF'S SUGGESTION — ONE only. Offer exactly ONE best-fit extra dish or luxury add-on (a farm egg, shaved truffle, Ibérico in place of streaky bacon) with one line on why it fits this menu — never a ranked list, never on the card until I approve it. (Distinct from the rule-4 fill-out, which completes a menu with options.) 11) DESIGN — like the best restaurant existing in the world for this theme. Iconic address → study its real typography, paper, and tone; recreate the feel faithfully plus one tiny respectful signature (never a monogram). Invented house → design the card that WOULD be the world's best if it existed. Base palette (paper + ink) must differ from my last three log lines — accent swaps don't count, the base must change. One signature face + one quiet supporting face. Exactly ONE innovative gesture (a glyph, a hairline rule, a vertical numeral, an unusual fold) — not three. Blindfold test: with the title covered, the cuisine is obvious from the design alone. Taste test: would a guest fold this card and keep it? CREW CARDS = FUN: brighter palette, interactive formats (checkboxes, station tags, stamp-cards, tear-off corners) — and the name must still evoke a MOMENT and a PLACE ("Sotto i Portici", not a pun with no terroir). Deli / build-your-own go cooler and interactive — pick-labels, order-ticket aesthetics, the interactivity functional. Elegance always; playful is never cheap. 12) SETS, WEEKS, MULTI-HOUSE. "Send the boss options" = a set of 3 radically different cards — different base palettes, typography, and protein anchors — with the axis named ("the occasion plate / the appetite plate / the icon plate"). Several cards in ONE document = one full card per page, each with its own complete identity, sibling palettes forbidden inside the document. A charter week MAY share one family identity with varying accents — declare it up front. 13) OUTPUT — print-ready, no LaTeX. One page, never two — tighten before you spill. A single HTML file, self-contained except web fonts: Google Fonts in the head (print while online, or ask me and swap to system-font stacks for offline printing at sea), all CSS inline, an @media print block sized to A4 portrait 210×297mm (A5 fine for casual crew; landscape for build-your-own grids), margins:0, print-color-adjust:exact, so the card fills the page. I print from any browser: Cmd-P (Ctrl-P on Windows) → Save as PDF → A4 → margins: none. Reality check for the last metre: standard onboard printers cannot print borderless — a dark full-bleed design needs a borderless printer or a guillotine trim; otherwise prefer light paper-coloured backgrounds or keep a 5mm safe margin. Suggest the filename "Chef - YYYY-MM-DD_Guests-Dinner_Theme" — the date lives in the filename, never on the card. Plain text only if I ask for just the dish list. 14) HONESTY. Never invent sourcing, provenance, history, or health facts — every claim on the card must be true. If a named ingredient is implausible for my port or season, flag it and propose the swap; you design the promise, I keep it at the market. If you don't know, say so. 15) VALIDATION GATE — non-overridable, NO exceptions. Before any file: state the touchstone, a one-line design brief, the composition split, which restrictions or profile inference you applied, and your one rule-10 suggestion; show the full dish list exactly as it will read on the card; WAIT for my explicit "yes / go / validated" — even for crew cards, even when I named every dish myself. Then output the HTML, tell me to print-preview it (Cmd/Ctrl-P) and confirm it fits ONE page — if it spills, tell me exactly which block to tighten — and close with the rule-1 log line.

A real session, request to PDF

The validation gate comes before any file is built — you see the dishes before the file system does.

Your request
Guest dinner, Italian, Harry's Bar feel. Eight covers, one coeliac, owner hates fennel, Mr B won't eat onions. Branzino and a veal dish. Complete it.

A It anchors and checks first. Touchstone: Harry’s Bar Venezia, a faithful homage. It reads the restrictions, strictest first — the coeliac guest governs the composition (no flour-thickened sauces, no bread on shared plates, a designed gluten-free substitution for the one dish that needs it, named in chat); then no onions anywhere, in any form; fennel swapped for another bitter element. None of this is printed on the card — allergies are handled in the food, not on the menu.

B It runs the palette pre-flight. It reads the last three menus it made for you, names their base palettes, and picks one that differs — so this card won’t look like last Tuesday’s.

C It presents the dish list and stops. You get the validation draft — touchstone, a one-line design brief, the composition split it chose (here: fire-leaning, so two vegetables and one salad), the dishes hero-first with middots, and ONE chef’s suggestion — then: “Any changes before I render? Wine pairing?” No file yet. This is the gate, and it is non-overridable.

D You say “yes,” and it renders. On an agentic tool it writes Chef - 2026-07-28_Guests-Dinner_Harrys-Bar-Venezia.html, renders it to a full-bleed A4 PDF with Chrome headless, verifies it’s exactly one page, opens it — then logs the touchstone and palette into its memory. On a chat model, it hands you the HTML and you print it. Either way the metadata lives in the filename; the card stays clean.

The whole exchange takes under two minutes. The scramble from the top of this article is gone — not because the AI cooked, but because it absorbed every standard you would have applied by hand, remembered every card it already made, and refused to skip the one step (your approval) that should never be automated.

Getting the best results

Give it a real touchstone, not a cuisine. “A Da Vittorio Sunday lunch” produces a sharper menu than “Italian.” The more specific and real the anchor, the better everything downstream — dishes, typography, paper, ornament — hangs together.

Feed it the preferences once, in writing. Upload the guest-preference sheet (allergies, intolerances, strong dislikes, the kids’ no-gos) as a knowledge file or paste it at the top. A menu designed blind is a menu you re-check by hand.

Respect the validation gate — it is for you. The agent stops and shows you the dish list before rendering. That is your cheapest moment to swap a protein, catch a clash, or change the touchstone. Approve too fast and you only move the rework downstream.

Let the palette memory work. On an agentic tool, keep your menus in one folder so the sibling-palette pre-flight has a real history to read. On a chat model, paste your last two or three menu titles and palettes so it can avoid repeating them.

Name constraints, not dishes. You don’t need to specify every plate. Give the limits — eight covers, 80% prep ahead, no pork, the dorade that needs using — and let it compose. It fills a well-defined box better than it reads your mind. Take its one chef’s suggestion as an offer, not an order: keep it if it serves the menu, wave it away if not.

It does not cook. It gives you back the hours you never had for the cooking.

What it will not do for you

This is a tool, not a chef, and the prompt is honest about that — it even has a refusal section that makes it push back rather than fake competence. So this article should be honest too.

It does not know what is in your walk-in, what the market landed this morning, or that the “line-caught branzino” it named so confidently isn’t coming into this port this week. Its own rule is to flag an unhonourable source and propose a swap — but you keep the promise the card makes. Cross-check every named ingredient against what you can really get.

It does not have taste the way you do. It can anchor, compose, and lay out a coherent, authentic menu — it cannot tell you the veal you cooked last Tuesday was thirty seconds past, or that this table goes quiet after the third course. That judgement is yours and stays yours.

And it is only as safe as the preferences you give it. The hard-limit logic is genuinely good — name an allergy and the ingredient stays off every dish — but it cannot protect a guest from a restriction you never wrote down. The agent enforces the list; building the list is still the chef’s job, and always will be.

The one thing: a good prompt is just a chef’s judgement, externalised — twenty-one hard rules, a design system, a touchstone library, and a memory of every card shipped, applied every time without tiring at the end of a six-week charter. Paste it once. Keep your hands for the cooking.
